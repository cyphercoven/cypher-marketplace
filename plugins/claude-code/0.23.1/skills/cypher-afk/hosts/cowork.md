# cypher-afk on Cowork

The rules are in `../SKILL.md`. Cowork has no plugin hooks, so, as in chat, the thread rides on HANDOVER.md and the automatic summary.

- **Keep HANDOVER.md current after every task** (gateway `workspace_edit` with `if_sha256`): tick the item, update "Next (exact first action)", add queue entries. Also keep the project doc `claude/<slug>-status.md` pointing at it.
- **Owner return:** apply the main skill's next-local-morning response eligibility to daytime and overnight AFK. Before 05:00 turn-on uses that same-day morning; otherwise use the next day. Interim prompts preserve original `since`. Owning-session going-away instructions or literal "still AFK" preserve `since` before eligibility and renew it after eligibility; literal "still AFK" without an active owning period or from another session is inert. Only an actual eligible owner response or an opening explicit off ends AFK. Missing/invalid timestamps require explicit off. Missing/empty prompts and `Scheduled AFK morning report:` prompts preserve AFK and eligibility; an opening explicit off wins. Legacy `until` has no authority.
- **Waiting:** `job_poll` or `factory_events` inside a turn. For a job that outlasts the turn, use the host's same-session check-in (`send_later`) at its expected finish, re-armed if the job is still running and disabled once it has fired (`update_trigger {enabled: false}`, logged as `cypher-scheduled-tasks` says). If the session has no same-session check-in, the queue waits for the owner. Never a polling loop, never `fire_trigger` or `delete_trigger` (the auto-mode check refuses them from a session), and never a successor session while AFK.
- **Check before ending a turn:** if `- [ ]` items remain, take the next one instead of ending. If the turn must end with runnable work left, first arm `send_later` into this session (about 3 minutes out, naming the next HANDOVER step); re-arm it each such turn; disable it when nothing runnable remains (W-45).
- **Reports and queue:** a 09:00 morning report is a progress snapshot. Keep AFK on and continue remaining authorized runnable work in this session. Record an early empty or owner-blocked-only queue as queue status without an early morning report. This may end the current turn but never AFK; distinguish it from all authorized work being complete. Reports never start a successor or create a scheduler/wake mechanism.
- **Context:** the automatic summary replaces early turns; the AFK lines and queue in HANDOVER.md are what survive, so never leave a decision only in the chat.
